# Flutter プロジェクト アーキテクチャ

## ディレクトリ構成

`lib`ディレクトリ配下が Flutter の開発で使うものなので、そこに絞って説明します。
本プロジェクトのディレクトリ構成は以下の通りです。

```
├── gen
└── src
    ├── environment
    ├── features
    │   ├── home
    │   │   └── pages
    │   ├── onboarding
    │   │   ├── pages
    │   │   └── state
    │   └── splash_screen
    │       └── pages
    ├── rest_api
    ├── router
    └── theme
    └── app.dart
└── main.dart
```

| ディレクトリ or ファイル | 責務                                                 |
| ------------------------ | ---------------------------------------------------- |
| gen                      | 自動生成用のコマンドなど                             |
| src/environment          | 開発・検証・本番などの環境の切り分けや設定内容       |
| src/features             | 機能単位で UI やロジックなどの実装一式               |
| src/rest_api             | REST API のコード一式                                |
| src/router               | 画面遷移コード一式                                   |
| src/theme                | Material Design に沿ったアプリのテーマ設定一式       |
| src/app.dart             | アプリ全体で共通化したい初期化処理などをまとめたもの |
| main.dart                | アプリのエントリポイント                             |

### Layer First? Feature First?

筆者の個人的な感想ですが、ディレクトリ構成は大きく分けて `レイヤー優先` と `機能優先`の 2 つの流派に分かれると思っています。筆者は、機能分けを推進しています。機能が多くなればなるほど、機能単位でディレクトリを切ったほうが管理しやすい為です。

レイヤーで分ける場合はこんなイメージです。

```
├── lib
│   ├── model
│   ├── repository
│   ├── view
│   ├── view_model
```

機能で切るとこうなります。

```
├── features/onboarding
│   ├── pages
│   ├── state
│   ├── model
│   ├── repository
```

### features ディレクトリ構成

| ディレクトリ | 責務                                                              |
| ------------ | ----------------------------------------------------------------- |
| pages        | UI の記述を行う箇所。ページ遷移等によって複数ある場合、複数個作る |
| state        | UI 操作に基づき状態を管理(最新化)する等の制御を行う               |
| model        | 外部データ通信・UI 操作に伴うデータの型を定義                     |
| repository   | データの CRUD を行う                                              |

機能で切ったとしても、レイヤーで分ける必要はあります。単体、つまり外部通信やローカルファイルなどに依存しない状態で UI テストができるようにするためです。
